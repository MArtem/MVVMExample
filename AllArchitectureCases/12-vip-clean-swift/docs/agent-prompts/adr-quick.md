You are a Staff iOS Architect.

Create a practical Architecture Decision Record for a production SwiftUI iOS app.

Context:
- SwiftUI
- iOS 17+
- feature-based MVVM
- small team 2–3 iOS developers
- best practices without overengineering
- AI-assisted development is part of workflow
- project should live 3–5 years

Decision topic:
[PASTE TOPIC]

Problem:
[PASTE PROBLEM]

Current situation:
[PASTE CURRENT STATE]

Options to consider:
[PASTE OPTIONS OR PROPOSE 3 OPTIONS]

Create an ADR with:

1. Title
2. Status
3. Context
4. Goals
5. Non-goals
6. Decision drivers
7. Options considered
8. Selected decision
9. Rationale
10. Positive consequences
11. Negative consequences
12. Accepted trade-offs
13. Concrete architecture rules
14. File structure impact
15. Dependency graph
16. Migration plan
17. Testing strategy
18. Swift Concurrency implications
19. AI-generated code implications
20. Release safety
21. Rollback strategy
22. PR review checklist
23. Good/bad Swift examples
24. Final recommendation

Be practical.
Do not overengineer.
Prefer the simplest production-safe solution.
Make the ADR useful for both human engineers and AI coding agents.
